# Sprint 1 Retrospective

## 1. What Went Well

The team successfully completed the main Sprint 1 User Stories.

The responsibilities were divided among team members clearly,
which helped the team work in parallel.

The team also communicated regularly during the development process
and used GitHub to manage the source code.

The database and basic application structure were established
early in the Sprint, providing a foundation for future features.

---

## 2. What Did Not Go Well

Some tasks took longer than initially estimated, especially tasks
related to database configuration and authentication.

The team also encountered several minor integration and UI issues
when combining different parts of the system.

Some requirements were not completely discussed before development,
which resulted in additional adjustments during implementation.

---

## 3. What Can Be Improved

For Sprint 2, the team will:

- Define acceptance criteria more clearly before implementation.
- Break large tasks into smaller tasks.
- Estimate task complexity more carefully.
- Communicate earlier when a blocker occurs.
- Perform integration testing more frequently.
- Use consistent coding conventions.
- Review completed work before merging it into the main branch.

---

## 4. Action Items for Sprint 2

### Action 1
Define clear acceptance criteria for every selected User Story.

### Action 2
Perform code review before merging changes.

### Action 3
Test database operations immediately after implementing
database-related features.

### Action 4
Hold short team discussions whenever a member encounters
a blocker.

### Action 5
Prepare Sprint 2 tasks before Sprint 2 starts.

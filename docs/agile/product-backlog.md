# Product Backlog

## 1. Project Overview

The Product Backlog contains the complete list of functional requirements
and User Stories for the e-commerce web application.

The backlog is prioritized based on business value and implementation
dependencies.

---

## 2. User Stories

### US-01 – User Registration

**As a** customer,  
**I want** to create a new account,  
**So that** I can use the shopping features of the system.

**Priority:** High

**Acceptance Criteria:**
- User can enter name, email, password and required information.
- The system validates the registration information.
- The system prevents duplicate accounts.
- A valid account can be created successfully.

---

### US-02 – User Login

**As a** customer,  
**I want** to log in to my account,  
**So that** I can access my personal information and shopping features.

**Priority:** High

**Acceptance Criteria:**
- User can enter username/email and password.
- The system validates the credentials.
- Invalid credentials display an error message.
- Successful login redirects the user to the appropriate page.

---

### US-03 – View Products

**As a** customer,  
**I want** to view available products,  
**So that** I can choose products to purchase.

**Priority:** High

**Acceptance Criteria:**
- Products are displayed with name, image and price.
- Products can be viewed from the product page.
- The system displays available product information.

---

### US-04 – Search Products

**As a** customer,  
**I want** to search for products,  
**So that** I can quickly find products that I need.

**Priority:** Medium

**Acceptance Criteria:**
- User can enter a search keyword.
- The system returns matching products.
- The system displays an appropriate message when no product is found.

---

### US-05 – View Product Details

**As a** customer,  
**I want** to view product details,  
**So that** I can understand the product before purchasing it.

**Priority:** High

**Acceptance Criteria:**
- User can view product name.
- User can view price.
- User can view product description.
- User can view product image.
- User can view product availability.

---

### US-06 – Shopping Cart

**As a** customer,  
**I want** to add products to my shopping cart,  
**So that** I can prepare the products before placing an order.

**Priority:** High

**Acceptance Criteria:**
- User can add a product to the cart.
- User can update product quantity.
- User can remove a product.
- The system calculates the cart total.

---

### US-07 – Place Order

**As a** customer,  
**I want** to place an order,  
**So that** I can purchase selected products.

**Priority:** High

**Acceptance Criteria:**
- User can enter delivery information.
- User can review selected products.
- The system calculates the order total.
- User can confirm the order.
- The system creates an order successfully.

---

### US-08 – View Order History

**As a** customer,  
**I want** to view my previous orders,  
**So that** I can track my purchases.

**Priority:** Medium

**Acceptance Criteria:**
- User can view previous orders.
- Order status is displayed.
- Order details can be viewed.

---

### US-09 – Manage User Profile

**As a** customer,  
**I want** to manage my personal information,  
**So that** my account information remains up to date.

**Priority:** Medium

**Acceptance Criteria:**
- User can view personal information.
- User can update personal information.
- The system validates updated information.

---

**Acceptance Criteria:**

- Admin can delete products.
- Admin can view product information.

---

### US-11 – Manage Categories

**As an** admin,  
**I want** to manage product categories,  
**So that** products can be organized properly.

**Priority:** Medium

**Acceptance Criteria:**
- Admin can add categories.
- Admin can edit categories.
- Admin can delete categories.
- Admin can view categories.

---

### US-12 – Manage Orders

**As an** admin,  
**I want** to manage customer orders,  
**So that** I can process orders efficiently.

**Priority:** High

**Acceptance Criteria:**
- Admin can view orders.
- Admin can view order details.

- Admin can manage order information.

---

### US-13 – Manage Users

**As an** admin,  
**I want** to manage users,  
**So that** I can control user accounts.

**Priority:** Medium

**Acceptance Criteria:**
- Admin can view users.

---

### US-14 – Contact / Feedback

**As a** customer,  
**I want** to send feedback or contact the store,  
**So that** I can ask questions or report problems.

**Priority:** Medium

**Acceptance Criteria:**

---

### US-15 – Admin Dashboard

**As an** admin,  
**I want** to view a dashboard,  
**So that** I can monitor the system.

**Priority:** Low

**Acceptance Criteria:**

- Basic system information is displayed.
- The dashboard provides access to management functions.
